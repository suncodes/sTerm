# 飞书完成通知与续问

在电脑端「设置 → 通知」开启飞书机器人。每个终端会话首次完成时，在目标群发一张卡片，之后的完成通知发回同一话题。

## 配置机器人

1. 在飞书开放平台创建企业自建应用，开启机器人能力。
2. 开启 **以应用的身份发消息**（`im:message:send_as_bot`）和 **获取群组中用户 @ 机器人消息**（`im:message.group_at_msg:readonly`）权限。在事件订阅中选择长连接，订阅 **接收消息 v2.0**（`im.message.receive_v1`）。
3. 发布应用，把机器人添加到目标群。在 sTerm 中填写 App ID、App Secret 和目标群 Chat ID（`oc_…`）。要在群里续问，可以填写一个或多个该应用对应的用户 Open ID（`ou_…`），用逗号或空格分隔。Open ID 留空时，可打开「允许群内所有用户续问」。留空且开关关闭时只发通知。
4. 打开「启用飞书通知」开关，开关状态会自动保存。填写机器人参数后点「保存」，配置完整时开始连接飞书。配置未完成时显示「待配置」。点「发送测试通知」，确认目标群收到消息。用实际完成卡片验证续问。长连接由电脑主动发起，电脑需要能够访问飞书。

飞书可能要求长连接已经在线才能保存事件订阅。先在 sTerm 开启飞书通知，再回到开放平台完成订阅和发布。[飞书长连接文档](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case)

## 使用会话话题

- Claude Code 和 Codex 使用现有原生状态上报。Pi 需要能报告 `agent_settled` 的版本，请更新 sTerm 的 Pi 扩展并重启 Pi。Agent 正常完成时发一条消息，等待审批、失败和退出时跳过完成提醒。
- 要续问，从目标会话完成卡片的「回复」入口进入话题，在话题内 `@机器人`，例如「继续运行测试并说明失败原因」。同一终端的话题可持续复用。sTerm 根据 Agent 当前上报的状态判断是否允许输入，就绪时可提交，无需再次完成一轮任务。运行中、正在提交、等待审批或其他交互、手机接管、会话失效和状态未知时会拒绝，不排队。只有 Agent 明确上报的交互状态才能被识别，未上报的 CLI 菜单无法统一判断。机器人接受普通文本，支持括号粘贴时可发送多行。Codex 续问保留段落换行，粘贴结束后单独提交一次。关闭或重启终端后，使用新会话发出的卡片。
- 原会话已分享，而且远程访问有可用的公网 HTTPS 地址时，卡片会出现「打开原会话」。已有浏览器授权时直接进入。启用 6 位访问码时，新浏览器输入访问码登录。未启用访问码时，卡片携带 5 分钟内有效、只能使用一次的临时配对凭证。链接失效或已用过时，授权用户可在同一话题中 `@机器人 打开会话` 获取新链接，该消息由机器人处理。配对链接的持有者可按当前分享权限访问远程会话。[远程访问说明](remote-access.md)
- 本地或远程输入、删除、移动光标不会使会话持续失去续问资格。飞书文本按普通终端输入语义在当前光标位置写入，然后提交回车；不会检查或清空草稿，已有草稿可能一起提交。打开页面查看、切换焦点和同步画面不影响续问。远程终端正在被接管时，请先归还控制权，之后重新按当前状态判断。若提交确认期间发生新的终端输入，仅拒绝本次请求；可在输入停止后重新发送，无需恢复操作。
- 手机或手表的提醒由飞书和系统通知设置决定。要测试锁屏提醒，开启飞书群通知后，用一轮真实任务验证。

卡片标题使用会话名称，正文显示 Agent 完成状态、会话编号与东八区完成时间（UTC+08:00）。设置中的「在卡片标题显示会话名称」关闭时，标题使用「终端会话」。飞书凭证按当前 Windows 用户加密保存。[隐私说明](../PRIVACY.md)
