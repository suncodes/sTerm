## 目标与范围

网页新增“Agent”模式，使用响应式消息页面展示结构化会话。电脑保留 Agent 原生终端，终端与网页始终作用于同一运行实例、同一会话，两端均可提交操作，无需交接控制权。

首版交付：

- 已接入且由电脑端授权共享的活跃会话列表、工作目录、Agent 类型和实时状态。
- 网页切换会话，查看当前会话已有历史及后续流式输出。
- 用户消息、助手文本、协议提供的思考摘要、工具参数、工具结果、执行状态、错误和中断状态。
- 文本输入、运行中追加、停止、模型选择、审批；权限切换按各版本实际能力提供。
- 多浏览器查看与操作、刷新恢复、断线补齐、逐会话草稿。
- 手机、平板、桌面分别排版；网页宽度不触发原生终端 resize。

首版保证范围：

- 优先保证从 sTerm 的 Agent 启动入口启动或恢复的会话：Claude 自动带 Mod，Codex 原生 TUI 明确绑定共享 app-server。
- 已运行普通 CLI 仅在探测到兼容桥接/共享后端时接入；不自动终止它、不注入未确认能力，不把启动第二个历史恢复进程称为共享。
- 网页切换活跃会话是改变订阅目标，不会切换其他终端的会话。
- 首版不包含任意休眠历史的远程恢复、网页创建新进程、附件上传、文件编辑器、终端自定义 UI 全量复刻。
- 本轮不规划 Pi 适配、Android 原生 App、多机器 Hub、官方云端 Remote Control。
- 终端模式与 Agent 结构化模式通过各自通道同时支持同一运行实例，沿用统一分享权限；原始终端仍需接管并校验控制 epoch，接管不禁用结构化 Agent 操作。启动 Agent 保留终端分享，Agent 退出后终端继续使用原 Shell。

## 架构与技术选择

复用 Rust/Tokio/Axum 服务、TypeScript/Vite 和现有纯 TypeScript 界面，不因新增模式迁移前端框架。

连接关系：

- Claude：原生 TUI + sTerm Mod → 本地 AgentHub。
- Codex：原生 TUI --remote → 同一受控 app-server ← Rust Codex Adapter → AgentHub。
- 网页：AgentHub → 现有远程访问服务 → Agent 模式页面。

sTerm 保持一个对外网页入口；Agent 内部连接不向浏览器直接公开。Claude 需要稳定的本地 HTTP 桥接端点，Codex 受控 app-server 如需监听则仅绑定 loopback 并启用认证，这些属于内部通信端点，不是每个 Agent 各开一个对外网页服务。

AgentHub 与远程网页开关分离：关闭网页访问仅撤销浏览器连接与分享能力，不终止原生 Agent，也不让 Claude Mod 的通信等待阻塞其运行。内部桥接生命周期由 sTerm 管理。

Codex 首版采用可明确控制的后端绑定方式：由 sTerm 启动一个兼容的本地 app-server，允许多个 thread；原生 TUI 与 Rust Adapter 同连该后端。接入现有默认 daemon、Windows proxy/control socket 的自动发现放在后续，不作为首版前提。不得重启或停止用户已有且不属于本次启动的 daemon。

## 公共数据与行为

### 身份与能力

每个运行实例记录 runtimeId、Agent 类型、CLI 版本、原生 sessionId/threadId、终端 tabId 与 generation、连接状态、能力清单、当前模型和当前策略。

不要用窗口标题、cwd 或历史文件名猜测运行实例绑定。启动时签发绑定凭据，由握手确认原生身份；进程或会话替换时提升代际，拒绝旧请求。

能力清单区分：

- 读取历史、实时输出、发送、运行中队列、停止当前回合。
- 模型列表与模型切换。
- 当前权限读取、当前权限切换、默认权限设置。
- 审批、问答、图片等独立能力。

界面按能力显示操作；不支持的操作展示具体原因，不模拟成功。

### 结构化协议

协议使用明确版本和序列号：

- SessionSnapshot：会话当前状态、消息、工具、待审批、设置与能力。
- AgentEvent：状态、message started/delta/completed、tool started/updated/completed、approval requested/resolved、settings changed、error。
- AgentCommand：sendText、stopTurn、setModel、setPolicy、respondApproval。
- 关联信息：runtimeId、sessionId、generation、turnId、itemId、requestId、commandId、seq；设置操作另带期望的设置修订号。

网关负责缓存命令结果和去重，Adapter 向 Agent 提交后由原生结果决定成功与否。收到命令不等于已执行。重连后优先查询命令状态；对结果不明的输入不自动重发，避免重复收费和工具执行。

初次连接返回快照与事件游标。后续按游标回放；窗口不足时重新取快照。消息以 itemId 合并，避免最终历史与流式文本重复。Delta 合批、队列和工具输出设置大小限制，慢网页不能拖住原生输出。

### 并发与审批

- 两端可以同时提交；执行和队列语义由原生 Agent 决定，界面显示已接受、排队、执行、完成或失败。
- 停止绑定明确 turnId；停止当前回合与清空队列分别声明。
- 模型/权限的冲突与忙碌限制按上游处理，并读取实际状态确认。
- 审批绑定原生 requestId 和会话代际；由 Agent 确认最终决定，sTerm 同步其他网页。
- 必须观察终端先审批、网页先审批、多个网页同时回复的结果，禁止把 sTerm 内存中的先到请求直接当成上游已经接受。
- 会话切换、停止、取消、超时后撤销待办，迟到回复不能审批下一次调用。

### 鉴权与共享

复用现有浏览器配对、登录、撤销和明确的会话分享授权。Agent 连接使用独立本地凭据，不复用浏览器 cookie，也不向网页传输模型 API Key。

现有 remote.rs 的 Origin 中间件针对浏览器；Claude 本地 HTTP 客户端没有浏览器 Origin。新增独立的本地桥接路由与凭据校验，不能为了让 Mod 连通而放宽所有 /api 路由的 Origin/CORS 规则。

共享列表只公布用户已授权的会话。允许查看与允许操作分别校验，但不引入独占控制人。原生终端始终能操作，远程操作必须经过服务端权限检查。

## 分阶段工作

按一名熟悉仓库的开发者连续投入估算，包含开发与联调。阶段时间是估算，不是协议兼容性保证。

### P0：验证门槛与版本能力表，2–3 个工作日

交付：

- 固定首批验收版本：本机 Claude 2.1.322、Codex 0.170.0；记录命令、API/schema 和能力，不擅自升级 CLI。
- Codex 隔离集成实验：真实 TUI --remote + 第二协议客户端，验证同后端同 thread、双向输入/输出、审批、停止、模型/策略设置。
- Claude 补测：终端决定后网页待办及时关闭、桥接断线不会卡住原生输出、同时多个会话、当前权限切换。
- 跨两 Agent 的能力矩阵与事件/命令最小协议。

退出标准：

- 两 Agent 各完成一条真正原生终端与第二客户端共用会话的操作链。
- 明确审批请求会发给哪些客户端、已决定请求如何关闭。
- 不通过时在此阶段确定上游兼容问题；不得通过换成另一进程恢复相同历史“达标”。
- 未验证的权限动作保持不支持，不阻止已验证基本功能的开发。

### P1：AgentHub 与会话接入，3–4 个工作日

交付：

- Rust 公共数据、会话注册、tab/generation 绑定、适配接口。
- 本地桥接鉴权、网页 API/事件通道、显式分享与操作权限。
- 有界事件缓冲、snapshot + seq 恢复、命令关联和去重。
- 启动入口及资源所有权记录；仅回收 sTerm 创建的子进程。
- AgentHub 生命周期独立于浏览器连接与远程服务开关。

退出标准：

- 用受控模拟 Adapter 验证会话隔离、越权拒绝、事件缺口恢复、命令不重复分发。
- 原有终端分享登录、接管和撤销回归通过。

### P2：Claude Adapter 与原生启动，3–4 个工作日

交付：

- 把验证 Mod 整理为随应用分发的资源，启动/恢复会话时通过 --plugin-dir 加载。
- 将会话、流、工具、模型、审批、停止转换成公共协议。
- 模型列表和网关自定义模型按 CLI 实际能力显示，不硬编码别名解析结果。
- 非阻塞事件转发；正常输出不能等待网页或跨网请求。本地桥接断连时继续提供原生审批，不自动允许工具；网页待办在重连后以原生实际状态为准。
- 处理 Mod 重载、会话变化、原生退出和错误。
- 当前权限读取与已验证操作；默认设置与当前状态分开。

退出标准：

- 在相同 sessionId 的原生 TUI 和测试网页上完成输入→流式→工具→审批→完成。
- 原生或网页任一侧停止/审批后，两侧状态一致。
- 网页关闭与远程访问关闭时，原生会话可继续使用。

### P3：网页 Agent 模式与 Claude 首次交付，3–4 个工作日

交付：

- 终端/Agent 模式入口、已共享活跃会话列表与切换。
- 消息、Markdown/代码块、工具卡片、状态、审批卡片。
- 输入框、发送/追加、停止、模型选择、按能力显示的权限操作。
- 小屏横向会话栏、独立滚动与输入布局；每会话草稿。
- 复用登录、分享链接和当前页面访问入口。
- Markdown 使用成熟解析器和安全渲染，沿用 CSP；仅展示上游提供的思考摘要。
- 切换会话时不销毁后台订阅状态，不把上一会话的迟到结果渲染到新会话。

退出标准：

- Claude 在正式 sTerm 页面完成桌面与手机宽度的双端操作。
- 调整网页宽度不改变原生 PTY cols/rows。
- 刷新、切会话与断线重连无重复消息、串话或草稿错位。

P3 完成时可交付第一版 Claude 体验；无需等待 Codex Adapter 全部完成。

### P4：Codex Adapter 与共享后端，4–5 个工作日

交付：

- 管理 sTerm 自有 app-server，使用带认证的本地协议连接。
- 原生 TUI 与 Adapter 明确使用同一个后端和 thread。
- 使用安装版生成的 schema/绑定核对 initialize、thread/turn/item、历史、模型、设置、审批和中断等方法。
- 将请求/通知映射为公共事件，不向网页直接暴露 app-server。
- 处理第二连接的订阅、审批广播与响应竞争、thread 关闭和后端退出。
- 使用原生接受的模型/策略更新机制，验证下一次请求与终端状态。

退出标准：

- 同一 threadId 在原生 TUI 和正式网页双向运行，不通过复制历史替代。
- 同时存在 Claude 和两个 Codex 会话时，可准确切换及操作。
- 审批在任一侧处理后其他端撤销待办；重复/过期响应不会影响其他 turn。

若 P0 发现平台缺口，P4 估算需据实际结果调整；不会用官方云端 Remote Control 替换本地路线。

### P5：稳定性、真实网关与发布检查，3–4 个工作日

交付：

- 两 Agent 与现有 API Key/兼容网关联调，验证实际模型 ID 与工具调用。
- 多浏览器竞态、长文本、工具大输出、弱网/断网、CLI 退出、Tab 重启、会话重载等测试。
- 分享与操作授权撤销、旧凭据、旧 turn、旧审批、跨会话输入的拒绝测试。
- 设置当前状态与默认值区别、能力缺失提示、安装/启用和恢复说明。
- README/remote-access 和已知版本限制更新。

退出标准：

- 下述验收清单全部满足；未支持的权限操作如实列出。
- 受影响 Rust 测试、前端构建、现有远程访问回归和真实 Chrome 集成检查通过。
- 所有本次临时进程与产物按项目规则清理，无法清理时报告残留。

总量约 18–24 个工作日，日历安排建议留 4–6 周。Claude 首次可用交付约在第 2–3 周。Codex Windows 共享后端与审批行为是最大排期变量，P0 后重新校准。

## 首版验收清单

1. 同一 Agent 会话原生终端与网页同时显示，sessionId/threadId 不变。
2. 模型未完成输出时，网页已经收到并显示文本。
3. 终端与网页在运行期间均能提交，显示原生接受或排队结果，无重复发送。
4. 模型切换反映到真实状态与后续请求，失败有回执。
5. 原生端或网页端批准/拒绝后，其余端待办关闭；迟到回复无效。
6. 网页停止只针对指定活跃 turn，不误杀其他会话，也不暗示队列已清空。
7. 至少覆盖两个 Claude、两个 Codex 的会话路由与网页切换。
8. 网页刷新与断线恢复后历史、流式尾部、待审批不重复、不丢失。
9. 手机 360/390、平板 768、桌面 1440 CSS px 可正常使用，网页宽度变化不触发终端 resize。
10. 撤销分享或操作权限后，已有连接和排队中的未执行网页操作均按新权限拒绝。
11. 关闭网页、远程访问开关或某个网页连接不会终止原生 Agent。
12. Claude 当前权限、默认权限及 Codex sandbox/approval policy 分别按真实能力展示。

浏览器自动化显式使用 Google Chrome。优先用本地模拟模型做可重复的流式、工具与竞态验证，再进行少量真实网关联调。临时配置、profile、截图与日志统一置于项目 .tmp，不访问或改写真实凭据用于模拟测试。
